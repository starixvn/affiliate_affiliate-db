## Shared Reporting Patterns

**Hybrid Data Split**: 
* Historical (<= AFF_CommissionDate) uses rptMemberDaily
* Recent (> boundary) uses DepositInfo for deposits / counts
* Pre-computed commission boundary = AFF_CommissionDate + 1 day

**Currency Normalization**: 
* CROSS APPLY Aff_f_ExchangeRate_Sel(date, sourceExchangeId, @BaseExchangeId) applied at aggregation boundaries

**Timezone Adjustments**: 
* Click statistics convert between GMT+8 (app logic) and GMT-4 storage
* deposit CreateTime from GMT+0 adjusted to GMT+8

**Paging**: 
* Row-number window specification with dynamic ORDER BY based on @SortType / @IsSortAsc / @SortDirectionType

**Temp Tables**: 
* All heavy reporting SPs rely on temp (# or table variables) for intermediate aggregation
* Lifetime ends inside procedure (no side effects outside transactions / adjustments SP)

### Aff_Admin_StatementHistory_Sel

PURPOSE: Returns paged monthly statement history for a single affiliate (earnings, payments, adjustments, CPA tentative/approved, sub‑affiliate commission, running balance brought forward). Supports hybrid commission: calculated months (<= AFF_CommissionDate) vs uncalculated/current months (> boundary) with tentative rows. Includes CPA tentative & approved earnings, sub‑affiliate revenue share, adjustments and payout rows, and running B/F balance per month.

BUSINESS RULE:
* Statement spans [@FDate, @TDate]; defaults to min report date -> today if nulls supplied.
* Commission rows split into: Calculated (final) vs UnCalculated vs Current (temporary) based on AFF_CommissionDate and current date.
* CPA earnings: Tentative (holding qualified but not settled) and Approved (TransType 206) + CPA adjustments (208) + Sub‑Affiliate RS (204 when CPA/Hybrid).
* Payments (202) shown as absolute amounts with Status from AffTrans; adjustments (203) as B/F.
* Running balance logic external (consumer may sum). Procedure groups trans types into description buckets.

PARAMETERS:
 
| Name | Type | Notes |
|------|------|-------|
| @AffId | INT | Target affiliate (must exist) |
| @FDate | SMALLDATETIME | From date (normalized to date; min bounded) |
| @TDate | SMALLDATETIME | To date (normalized; must be >= @FDate) |
| @PageSize | INT | Page size (default 50) |
| @PageIndex | INT | 1-based page index |
| @NRows | INT OUTPUT | Total qualifying rows (TransType <> 204) |

DERIVED / TEMP TABLES:
 
* @AffGroupInfo: affiliate group type per month for classification.
* #tempData: Unified statement rows (TransId, MonthDate, TransType, Amount, Status, Creator, Description, CalculatedType).
* #tempData_CPA: Raw CPA related transactions (206,204,208) pre-aggregation.

READS FROM:
 
* Aff_f_GetMinReportDate(), Aff_f_AffGroupInfo_Sel(), AffTrans, MemberCPA, CommGroup(+History), CPAGroupSetting, SystemSettings, AffPayout, Affiliate_User.

WRITES TO: (none – temp tables only).

VALIDATION:
 
* @FDate/@TDate auto-corrected; abort if @FDate > @TDate.
* Affiliate existence indirectly via min report date function (assumed valid if returns value).

LOGIC FLOW (SUMMARY):
 
1. Normalize date range & compute @EndOfTDate, commission boundary, current date.
2. Populate @AffGroupInfo for month classification.
3. Build #tempData/#tempData_CPA.
4. CPA section: tentative (StatusId=2 holding qualified) limited by remaining quota; approved CPA (206); sub-aff RS (204); CPA adjustment (208).
5. Payment/adjustment (202/203) rows inserted with timezone adjustment.
6. Revenue share earnings: Calculated months via AffTrans (201/204); Uncalculated/Current via commission uncalc pattern (#TempCommission + recursive month enumeration) with descriptive labels.
7. Paging via DENSE_RANK ordering: MonthDate DESC then TransId.

DECISION TREE:
 
* Is CPA/Hybrid? Include CPA and sub-aff rows.
* Month classification: Month <= @MaxCommDate -> Calculated; Month > @MaxCommDate and < current month -> UnCalculated; Month >= current month -> Current.

SIDE EFFECTS: None (read-only aside from temp objects).

EDGE CASES:
- No CPA quota (Quota=0) => tentative uses all eligible statusId=2 members.
- Empty month yields no rows; @NRows becomes 0 early exit.

IDEMPOTENT: Yes.

PERFORMANCE NOTES:
- Uses recursive CTE for month enumeration (MAXRECURSION 0). Potentially heavy for wide ranges; bounded by typical affiliate lifespan.
- Aggregations rely on appropriate covering indexes (TransType, WinlostDate, AffId) – tune if slow.

SAMPLE I/O:
- Input: @AffId=101, @FDate='2025-07-01', @TDate='2025-10-31'. Output rows include revenue share (201), sub-aff (204), approved CPA (206), adjustments (208), tentative CPA (209), payouts (202) with paging.

DEPENDENCIES:
- SystemSettings (AFF_CommissionDate, TimeZone), Aff_f_GetMinReportDate, Aff_f_AffGroupInfo_Sel, AffTrans, MemberCPA, AffPayout, CommGroup, CPAGroupSetting.

### Aff_Admin_Report_PaymentCPA
PURPOSE: Returns paged CPA payment schedule rows per affiliate deal and schedule with status filtering and date view mode (EndSchedule / ApprovedDate / AdjustedDate). Provides totals and per-row final CPA amount incorporating adjustments.

BUSINESS RULE:
- Filter by affiliate username LIKE, deal list (@DealIds), status list, and date range applied to field determined by @ViewBy.
- Status 'Empty' => hide ApprovedDate, Redeposit players indicator (NULL). Final amount = AdjustedAmount if present else ApprovedAmount else 0.
- Redeposit requirement: TotalRequired = FLOOR(TotalEligiblePlayers * RedepositRate); status gating changed by redeposit success vs expiration.

PARAMETERS (key): @UserName, @DealIds (CSV GroupIds), @Status (CSV status strings), @ViewBy (1 EndSchedule /2 ApprovedDate /3 AdjustedDate), @FromDate/@ToDate, paging, @IsExportExcel.

TEMP TABLES: #data consolidated schedule rows with Rid for paging.

READS: rptAffiliateCPA (schedule facts), AffInfo, CommGroup, Schedule, SystemSettings (TimeZone).

WRITES: None (temp only).

VALIDATION: CSV lists parsed to table variables; absence of matches -> empty result / NRows=0.

LOGIC FLOW:
1. Parse filters into @Deals, @Statuses.
2. Resolve timezone and current date for IsEnabled gating (60-day window).
3. Insert qualifying rows computing derived RequiredRedepositPlayers, FinalCPAAmount, StatusId, IsEnabled.
4. Page and return row subset plus totals sum.

EDGE CASES: Status='Empty' forces NULL ApprovedDate & Redeposit display. AdjustedAmount difference column (ManuallyApprovedDate logic).

PERFORMANCE: Rid ordering by (AffId, GroupId); consider indexing rptAffiliateCPA on GroupId+date columns for predicate efficiency.

DEPENDENCIES: rptAffiliateCPA, CommGroup (RedepositDays/Rate), Schedule, AffInfo, SystemSettings.

### Aff_Admin_PaymentCPA_Adjustment_Ins
PURPOSE: Inserts a CPA adjustment transaction (TransType 208) and updates payment schedule row with adjusted amount, description, audit log.

BUSINESS RULE:
- Only permitted if affiliate Status='Approved' and payment schedule Status in ('Qualified','Not Qualified').
- Amount recorded in AffTrans (Positive money); AdjustedAmount column becomes @NewAmount; AdjustedDate set to current (WinlostDate derivation using timezone); difference between new and approved captured implicitly for reporting.

PARAMETERS: @AffID, @UserID, @PaymentID, @NewAmount (final), @AdjustAmount (transaction delta), @TransDesc.

READS: SystemSettings(TimeZone), rptAffiliateCPA (schedule row), AffInfo (affiliate status, currency), TpExchange + Aff_f_ExchangeRate_Sel (rate), Aff_Con_CheckPermission.
WRITES: AffTrans (insert), rptAffiliateCPA (update), Aff_UserLog_RunSP_Detail_WriteLog.

VALIDATION & ERRORS: Affiliate existence (102), not approved (103), invalid payment schedule status (105), transaction failure (104). Permission check first.

LOGIC FLOW: Permission -> affiliate load & status check -> payment schedule status check -> TRY/CATCH insert/update -> write log with scalar key/values.

SIDE EFFECTS: Creates financial transaction and mutates schedule totals.

EDGE CASES: Unlimited schedule statuses ignored; if schedule not in eligible statuses returns error.

IDEMPOTENT: No (adjustment can be repeated changing financial history).

DEPENDENCIES: rptAffiliateCPA, AffTrans, Aff_Con_CheckPermission, Aff_f_ExchangeRate_Sel, Aff_UserLog_RunSP_Detail_WriteLog.

### Aff_Admin_Report_PlayerCPA
PURPOSE: Player-level CPA lifecycle report with Active, Holding, Redeposit, Approval phase indicators, amounts, dates, and derived status text.

BUSINESS RULE:
- Filters by affiliate username, player username, deal list, CPA StatusId list, view mode controlling date dimension (Active vs Holding qualified date).
- Status text mapping to lifecycle states; IsAbnormal when StatusId=4 (Rejected). EstimatedCPAAmount shows CPAAmount for statuses in (2,3,5,6) else 0.
- Redeposit indicators present only when ExpiredRedepositDate not NULL.

PARAMETERS: @UserName, @CustName, @DealName (GroupIds CSV), @StatusId (CSV), @ViewBy (1 ActiveQualifiedDate /2 HoldingQualifiedDate), @FromDate/@ToDate.

TEMP: #data consolidating MemberCPA row enrichments.

READS: MemberCPA, MemberInfo, AffInfo, CommGroup, Schedule.
WRITES: None.

LOGIC FLOW: Parse filter sets -> populate #data with computed flags (IsFTD, IsTotalDeposit, IsTO, IsHolding, Status text) -> return rows + aggregate sums.

EDGE CASES: Status text fallback; holding fields nullified when not holding; red deposit fields null when expired date is null.

DEPENDENCIES: MemberCPA schema, CommGroup schedule & holding definitions.

### Aff_Admin_AffiliateReport_Sel
PURPOSE: Multi-affiliate summary metrics across date range (monthly or arbitrary date range) combining hybrid historical vs recent deposit logic, commission/tier calculation, CPA qualified counts, click statistics, signup/FDM metrics, fees, earnings (rev share + CPA + sub-aff). Supports rich sorting & paging.

BUSINESS RULE:
- Hybrid: rptMemberDaily for months <= AFF_CommissionDate; DepositInfo for > boundary.
- Exchange rate normalization applied at month granularity via Aff_f_ExchangeRate_Sel.
- Qualified CPA players = settled + min(remaining quota, eligible holding-qualified) when current month; unlimited quota handled as NULL remaining.
- Extensive filtering: username, language, payment currency, statuses, group ids, product ids, date monthly mode vs direct.
- Sorting by multiple derived numeric columns; negative BFF exclusions controlled by flags.

PARAMETERS: Large set (filter, currency, sorting, paging). See source for full list.

TEMP TABLES: #TempCommission, #Statistics, #Signup, #TotalDeposit, #AffTrans, #CPA, #Result.

READS: AffInfo, AffDetail, CommGroup(+History), Schedule, MemberInfo, rptMemberDaily, DepositInfo, AffTrans, ClickStatistics (+_bk), MemberCPA, SystemSettings, TpExchange, CPAGroupSetting.
WRITES: Temp only.

LOGIC FLOW (HIGH LEVEL):
1. Normalize filters & currency mappings.
2. Build commission temp (calculated + uncalculated paths or direct daily path when @IsGetMonthly=0).
3. Collect click stats (Total/Unique) across current range from both live and backup tables excluding IsExcluded=1.
4. Collect signup, FDM count/amount & FDM total deposits hybrid.
5. Aggregate deposit counts & amounts hybrid (rptMemberDaily + DepositInfo).
6. Aggregate affiliate transactions (withdrawals, adjustments, CPA earnings) with exchange conversion.
7. Compute CPA qualified players (quota logic).
8. Merge into #Result applying sorting (ROW_NUMBER), then page.
9. Return detail + totals.

PERFORMANCE NOTES: Heavy multi-CTE and temp usage; rely on indexes (WinlostDate, AffId, CustId). Consider periodic optimization if range wide.

DEPENDENCIES: Commission calculation procs (Aff_Commission_Calc / UnCalc), Aff_f_ExchangeRate_Sel, Aff_f_AddRelatedProducts.

### Aff_Admin_Report_PlayersDetail_Sel
PURPOSE: Player-level activity & financial metrics for an affiliate over arbitrary date range with hybrid deposit separation, currency normalization, deduction fee application, optional removed player inclusion, sorting & paging.

BUSINESS RULE:
- Historical portion uses rptMemberDaily (<= AFF_CommissionDate); recent uses DepositInfo (+ currency scaling for VND/IDR /1000).
- Deduction fees (deposit/withdrawal) gathered per month from DeductionSettingHistory via affiliate group history, converted to base currency.
- Filters by product (expands related products), currencies, removed players flag, product/date boundaries.
- Returns IsCPADealOnly flag for UI gating.

PARAMETERS (key): @AffId, @ProductId, @FromDate, @ToDate, @Currencies (CSV), @BaseCurrency, @SortById, @IsSortAsc, @IsExportExcel, @PageIndex, @PageSize, @NRows OUTPUT, @IsIncludeRemovedPlayer (BIT - include players flagged as removed).

TEMP: #tmpDeductionSettings, #DataByMonth, #tmpData.

READS: MemberInfo, rptMemberDaily, DepositInfo, DeductionSettingHistory, AffGroupHistory, CommGroupHistory, TpExchange, Exchange, SystemSettings, MemberRemoval.
WRITES: Temp only.

SORTING: Complex CASE-based ORDER BY built on @SortById and @IsSortAsc across 14 selectable columns.

DEPENDENCIES: Aff_f_ExchangeRate_Sel, Aff_f_AddRelatedProducts, Aff_f_TpExchange_Sel, SystemSettings (AFF_CommissionDate, TimeZone, AffCurrency).
